## 昨日症状

两个重载：`combine(_: Int) -> Int` 与 `combine(_: Double) -> Double`。想在文档里链接后一个？
旧 DocC 只认 `combine(_:)-3c5j` 这种**短哈希后缀**——人是解码不出来的，
工具全靠 DocC 的 ambiguous 警告反向给你提示。写文档像解密。

## 为什么变

Swift 6.1 的 DocC 支持用**参数类型与返回类型**消歧：``combine(_:)->Double``。
到底最少要写哪几个，DocC 的警告会一步步建议（Insert '->Double' 之类）——语义就在文字里，哈希退场。

## 诊断与「是否仍合法」

本条验证最有说服力的正是一对真实警告（同一构建里同时出现，如日志）：

```text
warning: 'combine(_:)' is ambiguous at '/DoccDemo'
  ├─ suggestion: Insert '->Double' for 'func combine(_ first: Double) -> Double'
  ╰─ suggestion: Insert '->Int' for 'func combine(_ first: Int) -> Int'
```

typed 链接 ``combine(_:)->Double`` 无警告；哈希后缀写法仍然合法可用。
官方入口见 [Ambiguous Symbol Links](https://docs.swift.org/documentation/docc/linking-to-symbols-and-other-content#Ambiguous-Symbol-Links)。

## 常见坑

- 需要 swift-docc-plugin 才能跑 `swift package generate-documentation`（本仓库 pin 官方 1.x 插件，构建时拉取一次）；
- typed link 与哈希是两套语法：迁移期可以逐步替换，警告里的 suggestion 就是现成的迁移提示。
