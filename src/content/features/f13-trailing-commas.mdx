## 昨日症状

尾随逗号在**数组 / 字典字面量**里历来允许（SE-0084 原文记录的既有行为：`Swift permits trailing commas after the last element in array or dictionary literal`）。
SE-0084（2016 年被拒的「allow trailing commas in more lists」提案）在原文里也只是把它**记录**为现状，并尝试扩展到其余列表，未获通过。
所以 6.1 之前真正的问题不是「没有尾随逗号」，而是「只有字面量有」：函数实参、泛型列表、元组一律不行——格式化工具对每类列表单独写规则，代码生成器对「最后一个元素」特判。
SE-0439 这次带着 codegen 生态的论证卷土重来，获接受并在 6.1 落地。

## 为什么变

SE-0439 于 **2024 年 7 月被接受**（Accepted with modifications），**2025 年 3 月随 Swift 6.1 发布**。它把尾随逗号从数组/字典字面量**扩展**到：元组、函数参数列表、调用实参、泛型参数列表、闭包捕获列表、字符串插值内的调用。
动机之一就是 codegen：拼逗号列表不用再特判最后一项。它与被拒的 SE-0084 目标相似，论证与时机不同。

## 诊断与「是否仍合法」

诚实声明边界：SE-0439 **不是**「所有列表」。本站实测 6.2 工具链：
函数**类型**的参数列表 `(Int, Int,) -> Void` 与元组**类型**标注仍不接受（after.swift 的注释里点名了）。
另如上：数组/字典字面量的尾随逗号早就合法，不是任何 6.x 版本新增。
这两种位置想加尾逗号，报的就是「expected ',' separator」级别的解析错误——所以本条不设 broken 样本，
留给 after.swift 的注释当反面教材。

## 常见坑

- swift-format 的规则与团队的格式约定保持一致：尾逗号之争本质是 codestyle，语言只负责「允许」。

## 迁移检查

- [ ] 代码生成器删掉「最后一项特判」；
- [ ] 团队 codestyle 明确「允许但非强制」，防止变动风暴混进 git blame。
